# LEAN Proof-of-Concept Plan

> Created: 2026-07-21
> Purpose: Detailed plan for the first Dhan→LEAN backtest PoC.

---

## PoC Goal

One NSE equity
→ Dhan daily historical response
→ sanitized local fixture
→ conversion to native LEAN format
→ LEAN backtest
→ one deterministic result

**No live Dhan connection. No orders. No full universe. No database. No real
credentials in tests.**

---

## Constraints

| Constraint | Reason |
|-----------|--------|
| Daily resolution only | Simplest data format; intraday adds timezone/timestamp complexity |
| Single instrument | Validates format compatibility without universe complexity |
| Raw (unadjusted) prices | Factor files require verified split/dividend data; defer |
| No mapping files | Mapping files require verified ticker history; defer |
| Deterministic result | Same input must produce identical output on every run |
| No Docker requirement for PoC | Run LEAN engine directly via `dotnet` for simplicity |

---

## Step-by-Step Plan

### Step 1: Select Test Instrument

**Criteria**:
- Must be an NSE equity (not F&O, not index)
- Must have at least 1 year of daily data available via Dhan
- Must have a simple, well-known ticker symbol
- Must not have had a ticker change in the last 5 years

**Selection**: Deferred until Dhan API connection is tested. The instrument
will be chosen after confirming:
- The exact ticker format Dhan uses (e.g., "RELIANCE" vs "RELIANCE.NS")
- The security ID (instrument ID) Dhan assigns to NSE equities
- The exact response shape for `historical_daily_data`

### Step 2: Create Dhan Data Fixture

**Action**: Create a static JSON fixture file that mimics the Dhan
`historical_daily_data` response for the test instrument.

**File**: `tests/fixtures/dhan_daily_response.json`

**Contents**: A realistic but synthetic response with:
- 1 year of daily data (252 trading days)
- Valid OHLCV values (close within high-low range)
- Volume in realistic range

**Why fixture**: Eliminates live API dependency; makes tests deterministic;
keeps credentials out of tests.

### Step 3: Build Converter Script

**Action**: Write a Python script that:
1. Reads the Dhan JSON fixture
2. Reconstructs timestamps from the date range
3. Formats each row as `YYYYMMDD 00:00,open,high,low,close,volume`
4. Writes the CSV into a ZIP file
5. Places the ZIP at `Data/equity/india/daily/{ticker}.zip`

**File**: `src/dhan_to_lean/converters/daily.py`

**Validation**: The converter must be tested against the LEAN data reader
to confirm the output is parseable.

### Step 4: Write Minimal LEAN Algorithm

**Action**: Write a Python algorithm that:
1. Adds the test NSE equity with `Market.India`
2. Sets the start and end dates to match the fixture data
3. On `Initialize()`: adds the equity, sets warm-up period
4. On `OnData()`: logs the received bar (for verification)
5. Reports a deterministic statistic (e.g., total volume, mean close)

**File**: `src/dhan_to_lean/algorithms/price_check.py`

**Key details**:
- Must use `self.AddEquity("TICKER", Market.India)` to register the symbol
- Must set `self.SetStartDate(...)` and `self.SetEndDate(...)` to match fixture
- Must use `Resolution.Daily`

### Step 5: Run Backtest and Capture Result

**Action**: Run the LEAN engine with the algorithm and data fixture.

**Method**: Two options:
1. **Direct `dotnet`**: Compile LEAN, place data in `Data/`, run via
   `dotnet QuantConnect.Lean.Launcher.dll`
2. **Via `lean backtest`**: Use the LEAN CLI with Docker

**Decision**: Use `lean backtest` with Docker for the PoC, as it provides
the exact same environment as production.

**Output**: Capture the backtest results JSON and verify:
- The algorithm received the data bars
- The deterministic statistic matches expected value
- No errors or warnings in the log

### Step 6: Validate Determinism

**Action**: Run the backtest twice with identical inputs. Compare:
- Result statistics (must be identical)
- Log output (must be identical)
- Execution time (must be similar, not identical)

## Success Criteria

| Criterion | How Verified |
|-----------|-------------|
| Dhan fixture is valid JSON | `json.loads()` succeeds |
| Converter produces valid LEAN ZIP | LEAN reads the ZIP without errors |
| LEAN algorithm runs without errors | `lean backtest` exit code 0 |
| Algorithm receives data bars | Log output contains bar data |
| Deterministic statistic matches | Computed value equals expected |
| Results are reproducible | Two runs produce identical output |

## Risk: Test Instrument Selection

The test instrument cannot be hardcoded until the Dhan API is called and the
exact ticker/security-ID mapping is confirmed. The PoC code must use a
configurable ticker that can be changed once the API is tested.

---

## Risk: LEAN India Data Support

While `Market.India` exists in LEAN source code, the completeness of India
equity support (symbol properties, market hours, mapping files) is not fully
verified. The PoC will expose any gaps. If LEAN cannot parse the data for
the test instrument, the fallback is Route B (Custom Data).
